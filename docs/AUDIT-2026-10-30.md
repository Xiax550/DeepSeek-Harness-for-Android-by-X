## P0（发布阻塞 / 会让声明失真）

### P0-1 分发包缺 6 份依赖许可文本

已安装 APK 的 `assets/licenses/` 只有 8 个文件：

```
LICENSE  NOTICE.md  THIRD_PARTY.md  OPEN_SOURCE_COMPLIANCE.md
AGPL-3.0.txt  Apache-2.0.txt  GPL-2.0.txt  GPL-3.0.txt
```

但同一个 APK 里实际分发了这些 MIT / PSF 组件（在 `payload/.../node_modules` 与
`app/libs/` 内），它们的声明文本都在仓库 `LICENSES/` 里、**没有进包**：

| 组件 | 应有文本 | 随包分发位置 |
| --- | --- | --- |
| Shizuku API | `LICENSES/Shizuku-API-MIT.txt` | `app/libs/shizuku-*.jar` |
| dshmarket | `LICENSES/dshmarket-MIT.txt` | `payload/.../node_modules/dshmarket` |
| undici（两份 vendored 副本） | `LICENSES/undici-MIT.txt`、`LICENSES/undici-web-fetch-MIT.txt` | 同上 |
| js-yaml | `LICENSES/js-yaml-MIT.txt` | 同上 |
| argparse | `LICENSES/argparse-Python-2.0.txt` | 同上 |

MIT 的条件是「版权声明与许可声明须包含在软件的所有副本中」，APK 就是副本；
Python-2.0 的声明条款同理。`THIRD_PARTY.md` 里写着「文本见 `LICENSES/...`」，
而用户拿到的包里没有这个目录，指针在成品上是断的。

**修**：`scripts/build_apk.sh` 的 `pack_apk.py` 参数里补齐 6 条（本包已改）。

### P0-2 PRoot 的对应源码（见 `docs/BUILD-PROOT.md`）

`libproot.so` 自报 GPL-2.0-or-later，字符串含
`/Users/ethan/Src/github.com/OpenMinis/MinisApp/deps/talloc/talloc.c`、
`native_offload/native_offload.c`、`MINIS_NOFF_DEBUG`、`PROOT_USE_LOADER_FOR_QEMU`。
上游 fork 与构建配方都是公开的，但配方**跨 NDK 世代不逐字节可复现**，因此必须
**自建并记录哈希**，而不是继续转发来路未记录的二进制。详见 `docs/BUILD-PROOT.md`。

## P1（该改，不改会持续误导）

### P1-3 同版本号的 APK 与仓库文本不一致

用 1.2.50 的 APK 内嵌文件与仓库 HEAD 逐字节比：

| 文件 | APK sha256 前 8 位 | 仓库前 8 位 | 结果 |
| --- | --- | --- | --- |
| `NOTICE.md` | `f270ea90` | `90c1b9f9` | 不一致 |
| `THIRD_PARTY.md` | `45798e9a` | `d1602412` | 不一致 |
| `OPEN_SOURCE_COMPLIANCE.md` | `9d5065cf` | `c0b93911` | 不一致 |
| 4 份 SPDX 文本 | — | — | 一致 |

另外 `build_apk.sh` 会拷 `AUTHORS.md`，而包里没有 —— 说明这个 APK 是**在文档改动
之前**打的包，版本号却已经是 1.2.50。后果：仓库里写着「对应源码缺口」，用户装上的
包里那份还是旧措辞；两个陈述互相打架。

**修**：发布前用当前树重打 APK；并在 `OPEN_SOURCE_COMPLIANCE.md` 发布清单里加一条
「核对 APK 内 `assets/licenses/` 与仓库一致」（本包已加，第 10 条）。

### P1-4 `SOURCE_SHA256SUMS.txt` 有 21 条与 git 内容不符

562 条全路径都存在（无失效路径），但逐条比对已取到的 387 个文件，有 **21 条哈希不符**：
`HOT`、`VERSION`、`VERSION_CODE`、`ROOTFS_VERSION`、`LICENSES/*.txt`、
`app/res/*.xml`、`app/AndroidManifest.xml`。把这 21 个文件的内容 LF→CRLF 后再算，
**21 条全部吻合** —— 清单是在有 CRLF 的工作区里生成的。

根因在 `.gitattributes`：`* text=auto` 加若干 `eol=lf`，但只覆盖
`.sh/.yml/.md/.java/.js/.mjs/.py/.ps1`，**没覆盖 `.xml`/`.txt`/`.json` 和无扩展名文件**
（`VERSION`、`HOT` 等）。Windows 检出（`autocrlf`）会把它们变成 CRLF，于是哈希不可移植。

**修**：`.gitattributes` 增加 `*.xml`、`*.txt`、`*.json`、`VERSION`、`VERSION_CODE`、
`ROOTFS_VERSION`、`HOT`、`SOURCE_SHA256SUMS.txt` 的 `text eol=lf`（本包已改），
并在 LF 工作区重新生成清单；`scripts/regen-source-sums.sh` 是本包提供的生成脚本。

### P1-5 贴图路径 `web/whale/` 已不存在

`THIRD_PARTY.md` 第 20 行与 `payload/opt/dsh/android/ball-web/coo/THIRD_PARTY_NOTICES.md`
第 28、44 行都指向 `web/whale/`。仓库里 `payload/opt/dsh/android/ball-web/coo/` 的实际
结构是 `tex/`（25 张身体分件）与 `feat/`（27 张表情件）共 58 张 PNG，**没有 `web/` 目录**；
手机上装的同版本也是同样的结构。即三处引用全部失效。

**修**：改为 `tex/` 与 `feat/`（本包已改）。顺手记一句：`THIRD_PARTY_NOTICES.md` 说围裙上
标了 OpenAI / Anthropic / Google / 阿里云 / Kimi / MiniMax 的商标，但 `tex/skirt.png` 上实际
只有 DeepSeek 的蓝鲸标志 —— 这句描述与实物不符，建议按实际重写，否则读者会以为包里带
了别家商标。

## P2（建议改）

### P2-6 `update.json` 里 `hot.manifest` 指向 raw.githubusercontent.com

```json
"hot": { "manifest": "https://raw.githubusercontent.com/itiswdwa/lanfeiyu/main/update.json" }
```

两个问题：

1. `raw.githubusercontent.com` 在部分网络（含本机实测）**取不到**，而这个 URL 正是热更新
   链路的入口；仓库里 `dshmarket` 早就为此改用 `cdn.jsdelivr.net`，这里没跟上。
2. 这个字段的内容就是 `update.json` 自己（自引用），客户端拿到它等于又拿一遍同一份清单，
   起不到「独立校验热包版本」的作用。

**修**：换成 jsDelivr 镜像（本包已改 `update.json` 与 `scripts/make_update_manifest.py`），
并考虑让 `hot.manifest` 指向真正的热包清单（`hot.zip` 里的 `hot.json` 或其独立副本）。

### P2-7 `docs/BUILD.md` 完全没提许可文本打包

`docs/BUILD.md` 讲了 aapt2 → javac → d8 → pack_apk 全流程，但一个字没说
`assets/licenses/` 里该放什么。这正是 P0-1 能长期存在的原因。
**修**：本包在 `docs/BUILD.md` 末尾加了一节「许可文本打包」（含打包后 `cmp` 自检命令）。
